# ジョブの識別と表示名・タグの保存

表示名とタグは、cron の5フィールドを除いたコマンド本文に関連付ける。引数・引用符・リダイレクト・末尾コメント・コマンド内部と末尾の空白を含む本文が同じなら、実行時刻・曜日・環境変数・タイムゾーンが違っても同じ表示名とタグを使う。

## 保存用の ID と表示行の ID

- `definition_id`：コマンドを識別する保存用 ID。表示名とタグはこの ID に保存する。
- `id`：`definition_id` に同じコマンドの出現連番（1始まり）を付けた表示行 ID。コマンド取得 API とタイムラインの task_id に使う。
- `duplicate_count`：今回収集できた範囲で、同じコマンドを持つ行数。時刻が異なる行も数える。

同じコマンドの行を統合せず、それぞれの実行条件・予定を表示する。行の増減や並べ替えで、以前の何行目が残ったかは判定しない。表示行の出現連番は表示名・タグの保存キーにしない。

## 変更ごとの扱い

| 変更 | 保存用 ID と表示名・タグ |
| --- | --- |
| 時刻・曜日・日付等の5フィールド | 維持 |
| タイムゾーン・環境変数・その宣言境界を越える行の移動 | 維持 |
| ジョブ行の順序、空行、独立したコメント行 | 維持 |
| 行頭のインデント、5フィールド間・コマンド直前のスペース／タブ、LF / CRLF | 維持 |
| 実行ファイル・引数・引用符・リダイレクト・コマンド内部／末尾の空白 | 別 ID |
| コマンド末尾のコメント・QTS の識別コメント | 別 ID |
| 同じコマンドの行の増減 | 維持。表示行数と実行予定は各行を反映 |
| 消えたコマンドの再登場 | 同じ ID。保存済みの表示名・タグを使う |

コマンド名だけを抽出したり、シェル構文を意味解析したりしない。標準の5フィールドとコマンドを分離できない行や @reboot 等の未対応行は、行全体をそのまま識別する。時刻の値が範囲外でもフィールドを分離できればコマンド本文で識別する。識別できることと、予定時刻を計算できることは別。

## ID の計算

分離可能な行は `['command', コマンド本文]`、未対応・分離不能行は `['opaque', 行原文]` を識別データとする。`['cron-v2', 識別データ]` を UTF-8 JSON（ensure_ascii=False、区切りは `(',', ':')`）にして SHA-256 を計算し、64桁の16進表記に `cron-v2-` を付ける。

取得日時・行番号・実行条件・実行環境・mount のパスは保存用 ID に含めない。コマンド本文は ID に埋め込まず、通常 API・ログ・DB には保存しない。ハッシュは暗号化ではなく、閲覧権限は既存のアクセス制御に従う。DB は QSV インスタンス単位で使い、複数 NAS 間で共用しない。

## 保存形式の互換性と移行

DB スキーマ1は、初期化時に同じディレクトリへ `qsv.sqlite3.before-v2-*.sqlite3` のバックアップを作成してからスキーマ2へ更新する。移行と表示名・タグの関連付け変更はトランザクション内で行う。失敗時に元の保存内容・スキーマを部分更新しない。

現在取得できた cron 行から、旧形式 cron-v1 の ID と新形式 cron-v2 の ID の対応を計算する。この対応で保存データを確認でき、表示名とタグが一意なら新しい ID へ移す。一致する複数の保存内容は一つにまとめる。移行後の現在の行では、一度共有された表示名・タグが時刻変更で外れない。

同じコマンドに異なる表示名・タグがある場合は、勝手に上書き・和集合を作らず、保存内容をすべて残す。ジョブ詳細の注意を確認し、「タグ・表示名」画面でコピーする内容を選ぶ。明示的な保存・コピー・リセットで選んだ内容を、自動移行が後から置き換えたり復活させたりしない。

すでに紐付けが切れ、旧 ID と現在の行との対応を確認できない保存データは保持する。旧 DB に当時のコマンド本文や cron 式はないため、時刻やコマンドを推測して自動復元しない。画面からコピー先を選択してコピーする。コピー API は cron-v1 / cron-v2 の両方を受け付ける。

互換性のために保存するのは ID 同士の対応と選択済み状態だけで、コマンド・環境変数・cron 式は DB に保存しない。退避したスキーマ1のバックアップも、新しいバックアップ・復元コマンドで扱える。

## 不在のジョブと明示コピー

表示名・タグは、コマンドが見えなくなっても利用者がリセットするまで保持する。完全取得（ok / empty）だけで不在を判定し、partial・取得失敗・タイムアウト・古いキャッシュでは不在と断定しない。収集上限500件のときの行数は、収集できた範囲の値。

別のコマンドに表示名・タグをコピーするときは、コピー元・コピー先と、影響する行の範囲を利用者が確認する。コピー元は残す。更新時に双方の版とコピー先の存在を検証する。QTS の crontab に識別子を書き込まない。

API・バックアップ・復元は [annotations.md](annotations.md) を参照。
