# セキュリティと制限

アプリは設定を読むだけで、コマンドやジョブを実行しない。読み取り元はプロセス起動時の環境変数で固定し、HTTP リクエストから指定できない。外部 API・CDN・クラウド送信を使わない。UI は textContent で表示し、生の設定文字列を HTML に挿入しない。CSP・nosniff・no-store を付与し、CSV の数式開始文字をエスケープする。

資格情報はキー名を持たない引数・パス・シェル構文にも入り得る。通常レスポンス・検索・CSV にはコマンド原文を含めず、静的 allowlist の実行ファイル名（hwclock 等）だけを表示し、その他は全体を非表示にする。詳細画面の各ジョブのコマンド行を押すと、そのタスクの全文を専用 API から取得できる。目のアイコンで表示・非表示を切り替える。表示される全文には資格情報を含む可能性があり、自動マスクは行わない。閲覧できる相手はスケジュールと同じで、Tailnet ACL とバックエンドのプロキシ IP 制限で制御する。

原文は QNAP の収集プロセスのメモリに保持し、通常モデルのシリアライズ・repr から除外する。ブラウザでは textContent で表示し、永続保存しない。「非表示」・詳細を閉じる・画面切替・再取得（定期更新を含む）で DOM から消し、取得中のリクエストも中止する。HTTP 応答には no-store を付与する。ただし、許可された閲覧者による保存やスクリーンショットを防ぐ機能ではない。

標準の5フィールドとコマンドを分離できる行は、時刻値の不正や TZ 指定で計算できなくてもコマンドを表示できる。フィールドの形を識別できない行と未対応の @reboot 等は原文 API の対象外とし、元の式も非表示にする。環境変数の代入行はタスクにしない。

ファイル読取の例外本文・元の行・秘密値をログやエラー応答に含めない。タスクの定義 ID は取得元・実行環境・cron 式・コマンドのバージョン付き SHA-256 で計算し、表示行 ID には同一定義の連番を付ける。同一定義の注釈を共有しても、実行予定は各行を残す。空白の正規化は cron のフィールド区切り等に限定し、コマンド・コメント・環境変数を意味解析して統合しない。式やコマンド等の変更後に注釈を自動で移さない。詳細は [ジョブ識別仕様](job-identity.md) を参照。

ブラウザ向け入口は server-a 上の QSV 専用 Tailscale ノードと Caddy の443に限定する。ホストの Tailscale と専用ノードの state/socket は共有しない。QNAP に Tailscale は導入しない。QSV のバックエンドは QNAP の指定 LAN IP・専用ポートで到達可能にし、アプリの allowlist で server-a の実際の送信元 IP 以外の要求に 403 を返す。TCP 接続自体を拒否する firewall ではない。LAN IP への bind は送信元制限ではない。独自認証がないため、この制限なしに LAN に公開すると Tailnet を経由しない閲覧が可能になる。

Tailnet ACL は server-a の入口を保護するものであり、QNAP の LAN ポートへの直接接続には適用されない。QSV はプロキシを経由する前のクライアント IP を検査しない。リバースプロキシへのアクセスは Tailscale ACL で制御し、そこに独自の IP allowlist は追加しない。QSV_ALLOWED_PROXY_IPS は中継するプロキシだけを列挙し、空は全拒否、不正な IP は起動エラーとする。

Docker の NAT によって実際の接続元を区別できなくなる経路がないか実機確認する。許可元・拒否元の両方から実測し、共通の gateway IP を安易に許可しない。必要なら既存のネットワーク側制限を併用する。[Docker のファイアウォールの説明](https://docs.docker.com/engine/network/packet-filtering-firewalls/) を参照。

Tailnet と server-a 間の暗号化は QNAP まで延長されない。ホーム LAN を信頼し、バックエンド HTTP + プロキシ IP 制限を採用する。追加の認証情報・パスワード・トークン・バックエンド TLS は要求しない。ブラウザ向け証明書・ACL・Funnel・IPv6 を含む確認事項は [deployment.md](deployment.md) を参照。

収集コンテナの host network、privileged、Docker socket、ホストの /etc 全体マウントは使用しない。QNAP の設定ファイルや権限をアプリから変更しない。許可されたプロキシとホーム LAN を信頼する構成であり、プロキシの侵害や LAN 内での IP 詐称を認証で防ぐものではない。


認証・ユーザー管理は実装しない。POST /api/refresh は異なる Origin のブラウザリクエストを拒否するが、認証の代わりではない。Uvicorn は --no-proxy-headers で起動し、プロキシヘッダーは信用せず、HTTPS プロキシ経由の Origin は Host の一致で判定する。

単一ファイル mount は QTS の atomic replacement に追従しない可能性がある。root しか読めない設定への対応や内部 DB の権限分離は未実装であり、必要と判明した時点で最小情報のスナップショット方式を検討する。
